<h2>一、隔离从来不是一层的事</h2>
<p>很多人以为换个IP就叫隔离，实际平台看的是整条链路：出口地址、浏览器指纹、设备信息、账号资料，四层一起判断。</p>
<p>只做一层，其余三层露出破绽，效果等于没做。四层都对齐，才算一个完整环境。</p>
<p>所以配置顺序应该是先链路、再会话、再设备、最后账号，从底往上，逐层验证。</p>

<h2>二、链路层怎么配</h2>
<p>链路层的核心是一条环境一条出口。静态住宅IP的配置方式有三种：客户端代理、系统代理、路由分流。</p>
<p>客户端代理最灵活，按进程分流，只让指定浏览器走代理，本机其他流量不受影响。</p>
<p>路由分流适合固定工位，整台机器或整个网段走一条线，员工改不了，管理成本低。</p>
<h3>DNS也要跟着走</h3>
<p>只代理网页流量不代理DNS，解析请求仍从本地发出，检测页一看就知道出口和解析地不在一个国家。</p>
<p>配置时把DNS指向出口侧的解析服务，或在客户端开启远程解析，这一项最容易被漏掉。</p>
<h2>三、会话层怎么配</h2>
<p>会话层的目标是让每个账号有独立的Cookie、缓存、LocalStorage，互不可见。</p>
<p>最简单的方式是给每个店铺建独立的浏览器配置文件，登录前确认配置文件与线路的对应关系。</p>
<p>更规范的做法是用环境管理工具，把配置文件、代理、账号打包成一个条目，一键启动。</p>
<h2>四、设备层怎么配</h2>
<p>设备层包括时区、语言、分辨率、字体、Canvas与WebGL特征，这些组合起来构成指纹。</p>
<p>同一台机器开多个环境，指纹很容易雷同，尤其是分辨率和字体列表，几乎不会变。</p>
<p>可行的做法是让每个环境使用不同的指纹模板，并且与出口城市的常见配置对齐，比如美国西部用太平洋时区。</p>

<h2>五、账号层怎么配</h2>
<p>账号层是最容易被忽略的一层。手机号、邮箱、收款账户、退货地址，任何一项重复都会把两个号连起来。</p>
<p>注册资料要按店铺独立准备，别用同一个手机号收验证码，也别在同一台手机上装多个店铺的验证应用。</p>
<p>资料的真实性由经营者自己负责，这里只讨论技术上的独立，不涉及任何身份伪造。</p>
<h2>六、验证隔离是否真的生效</h2>
<p>配完必须验证，不能靠感觉。每次新增环境，跑一遍五项检查：出口、DNS、时区、WebRTC、会话。</p>
<p>验证要在真实登录前做，登录之后再发现问题，异常记录已经产生了。</p>
<p>建议把检查结果截图存档，和环境编号放在一起，出问题时能快速定位是哪一层没配好。</p>
<h3>两个环境同时开一次</h3>
<p>把两个环境并排打开，分别查IP和指纹，如果两项完全一样，说明配置文件复制时把代理设置也带过去了。</p>
<p>这种情况在批量复制环境时特别常见，新增一个环境的第一件事就是检查代理是否为独立凭据。</p>
<h2>常见问答</h2>
<h3>换了IP还需要换浏览器吗？</h3>
<p>答：不一定要换浏览器，但必须换独立的配置文件。同一浏览器共用缓存和Cookie，换IP也隔不开。</p>
<h3>静态住宅IP能多个账号共用吗？</h3>
<p>答：技术上可以，隔离效果会打折。多账号共用一个出口，平台侧看到的是同一网络身份，出问题时难以区分。</p>
<h3>WebRTC泄漏会暴露什么？</h3>
<p>答：可能暴露本机的内网地址或真实公网出口，检测页能直接看到。配置时关闭WebRTC或限制其走代理。</p>
<h3>隔离做好就不会被关联吗？</h3>
<p>答：没有这种保证。关联判断涉及多维度信号，技术隔离只减少明显的一致性，不能消除全部风险。</p>
